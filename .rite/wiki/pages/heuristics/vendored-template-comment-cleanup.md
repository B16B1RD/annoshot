# vendor した生成テンプレートは消費者側で意味を持たないコメント参照を削除で解消する

## 概要

生成器のテンプレートをそのままコミットすると、削除済みマーカーや上流リポジトリ相対パスへのコメント参照が残り読者が追跡先を失う。設定値を変えず参照行だけ削除し、消費者側で意味を持つ情報のみ残すのが最小差分で、upgrade 差分ノイズとの天秤で判断する。

## 詳細

- 観測: セットアップウィザードが生成した設定ファイル（rite-config.yml）を消費者リポジトリへそのままコミットしたところ、テンプレート由来のコメント 7 箇所が本ファイルに存在しない `--- Advanced ---` マーカー、上流リポジトリ相対パス（docs/designs/*.md）、移動済みファイル名（init.md）を参照していた。生成器は Advanced セクション以降を省いて出力する一方、コメント側の自己参照は残るため、消費者側では追跡先のない記述だけが残る。
- 帰結: 指摘は全て文書整合クラス（実測アンカーなし）に留まり、実測必須ゲートで non-blocking に分類される。1 cycle で mergeable に収束するため、放置しても merge は止まらないが、読者の追跡先喪失として残る。
- 対処の型: 「追加より削除」。参照先が本リポジトリに存在しないコメント行を削除し、消費者側で意味を持つ情報（`--upgrade` 時の back-add 挙動と既存値の保全）だけを残す。設定値には触れない。
- 判断軸: 根本原因は上流テンプレートにあり、消費者側の手編集は次回 `--upgrade` の差分ノイズになる。軽微な削除で読者の混乱を防ぐ価値と、ノイズ増加のコストを天秤にかけ、削除が小さく済むなら消費者側で直し、上流にも報告する。
- 併せて観測された判断: Issue の Non-goal（例: GitHub テンプレートの文面カスタマイズ）に抵触する指摘は、判定文付きで却下し却下台帳に記録する。Non-goal を根拠に明示すると同じ指摘の再訴訟を防げる。
